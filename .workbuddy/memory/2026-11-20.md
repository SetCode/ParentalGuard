## ParentalGuard · 推送与首次发布（21:50-22:12）

- GCM 已存 `SetCode` 账号（`git credential-manager github login` 浏览器授权成功，换 token 那次报 `基础连接已经关闭` 但凭据仍落库），此后 `git push` 可正常使用，凭据在 Windows 凭据管理器内，我全程未接触 token。

- CI 首次失败根因：`gradlew` 在 Git 索引里是 `100644`（Windows 提交丢失执行位），Linux runner 上 0 秒退出。修复 `git update-index --chmod=+x gradlew` + 工作流加 `chmod +x ./gradlew`。
- 用户声称已加 `KEYSTORE_BASE64` 等 Secret，实际仓库 Secrets 为空（截图确认 `This repository has no secrets`），两次 Release 均卡在恢复签名步骤。
- 桌面控制不可用：`WORKBUDDY_COMPUTER_USE_BACKGROUND_DISABLED=1` 只留前台整屏；且虚拟桌面需用户输入 Windows 登录密码（`credential_required`），且独立桌面与主会话**剪贴板不互通**，无法用它粘贴密钥。`bsk` CLI 未安装（扩展装了也没用）。
- **最终方案（已落地）**：私有签名只在本地，APK 提交入库，CI 不碰私钥
  - `release.yml` 只做：校验 APK 存在 → 比对 sha256 → `aapt2` 核对包内 versionName 等于 tag → 生成说明 → `gh release create`（GITHUB_TOKEN，无需任何 Secret）
  - `tools/release.sh` 产物输出到仓库根目录，`--push` 时连 APK 与 `.sha256` 一起提交
  - `version.properties` = 1.0.1 / 10001
