# 儿童设备管控（ParentalGuard）

面向家长的 Android 设备管控应用，兼容手机与平板。以**完整可编译的 Android 工程**形式交付，包含配置界面、设备端限制逻辑、规则持久化、状态提示与运行时权限处理。

**计时范围严格**：只有目标应用真正处于前台才累计该应用时长；退出到桌面、切到别的应用、退到后台、锁屏/灭屏都会立即暂停，重新进入从暂停处继续累计，不重复、不回退、不丢失。

**完全离线的局域网共享**：应用可在本机启动内置 HTTP 服务器，同一 Wi-Fi 内其他安装本应用的设备可读取并更新同一份数据集；支持多个独立隔离的监控对象，配置、计时状态、累计时长与更新记录各自独立。全部数据保存在本机，**不经过任何云服务器**。

**提示面向儿童设计**：拦截和锁定都用大图标、鲜艳颜色、超大数字和**随应用内置的中文真人语音**说明原因，不依赖孩子识字，也不需要设备预装语音引擎、不需要联网；家长可分别设置是否出声、是否朗读、是否弹图形。

**计时信息精确到秒**：主界面与下拉通知栏都把「可用时长」「单次使用连续剩余时间」分开显示为 `00 时 00 分 00 秒`，每秒刷新；展开常驻通知即可同时查看，无需打开应用。

**两项设置仅本机生效**：「启用全部管控规则」与「应用白名单」不参与局域网同步，每台设备各自独立；其余规则、计时数据与监控对象仍在设备间保持一致（见 4.7 节）。

## 二、功能与规则语义

| 规则 | 行为 | 解除条件 |
| --- | --- | --- |
| 每日设备总使用时长 | 当日所有应用前台时长累计达到上限后，全设备锁定 | 次日 00:00 自动解除 |
| 单次连续使用 + 强制休息 | 连续使用达到上限后进入强制休息，休息期间限制设备使用 | 休息倒计时结束后，若其他规则允许则自动恢复 |
| 可玩白名单 | 名单外应用**一打开就立即送回桌面**，同时用大图标与中文语音说明原因 | 切换到允许的应用即解除；系统桌面与管控应用自动放行 |
| 休息放行名单 | 强制休息期间，名单内应用仍可正常使用；名单外应用被全屏拦截 | 休息结束后按其他规则恢复；只豁免「强制休息」这一条 |
| 免计时名单 | 名单内应用在前台时**不累计任何时长**（今日总量、单次连续、单应用时长都不增长） | 始终生效；只影响计时，不影响拦截判定 |
| 单应用每日累计时长 | 可为多个应用分别设置上限，超额后该应用当天禁止使用 | 次日 00:00 自动恢复 |
| 局域网本地共享 | 本机可启动服务器；同网设备读取并更新同一份数据集；多个监控对象各自隔离 | 断开后仍使用本机已保存数据 |
| 时间重置 | 主界面独立入口一键把当前监控对象的全部计时值恢复到预设初始状态 | 立即生效；只清计时，不改任何配置 |

**规则叠加**：所有启用的规则同时判定，命中项全部收集并展示；执行时按「更严格」择优：
1. 作用域更大者优先：全设备锁定 > 仅当前应用限制；
2. 同作用域下自动解除时间更晚者优先（例如「次日零点」胜过「切换应用即解除」）。

**三类应用名单的优先级与互不冲突保证**：

| 场景 | 判定 |
| --- | --- |
| 当前应用是管控自身 | 任何规则都不拦截（含强制休息），家长始终能进设置改配置 |
| 强制休息中 + 应用在休息放行名单 | 不产生「强制休息」锁；每日总时长、单应用限额、可玩白名单**照常生效** |
| 强制休息中 + 应用不在休息放行名单 | 全屏拦截（与改动前一致） |
| 应用在免计时名单 | 时长恒为 0，因此**永远不会**被每日总时长或单应用限额拦到；可玩白名单对它的拦截不受影响 |
| 应用同时在三类名单里 | 三个效果各管各的：放行、休息豁免、不计时；互不覆盖、互不抵消 |

三类名单**各自有独立开关**（默认开启）：关闭后名单内容保留但不再生效——可玩白名单关闭即全部放行，休息放行关闭即休息期间一律拦截，免计时关闭即全部照常计时。

三类名单都由 `RulesConfig.ensureSelf()` 强制加入管控自身（加载、写入、切换对象三处都会补齐），界面里该行固定勾选且不可取消。规则判定还有一道独立保险：`StateBus.selfActivityVisible` 由 Activity 生命周期维护，只要本应用界面在前台就直接按「本应用」判定，不采信可能滞后的使用统计，避免开启白名单后把家长从设置页踢回桌面。

**配置操作**：每条规则可独立启用/禁用；每日时长、连续/休息时长可修改；白名单应用可增删；单应用限额可新增、修改时长、单独启用/禁用、删除；另有管控总开关与四项儿童提示开关。修改后服务下一秒心跳即生效，无需重启。

**即时拦截**：无障碍服务在窗口切换事件到达的瞬间调用 `BlockJudge` 判定白名单 / 单应用限额，命中即 `performGlobalAction(GLOBAL_ACTION_HOME)` 返回桌面并弹出提示，不必等待 1 秒心跳；心跳仍作为兜底，且与即时拦截共用去重键，保证一次拦截只提示一次。全设备级限制（每日总量、休息）由全屏遮罩统一处理，不会误报「应用不允许」。

## 三、计数与生命周期

### 计时范围（目标应用前台才算使用）

| 状态 | 是否计入该应用时长 | 处理 |
| --- | --- | --- |
| 目标应用在前台（含界面内静止使用） | 是 | 片段持续累计，每 5 秒结算一次 |
| 退出到桌面并停留 | **否** | 窗口事件到达瞬间结算并清零片段起点，桌面状态不过期，停留多久都不计时 |
| 切到其他应用 | 目标应用**否**，其他应用**是** | 先结算旧片段、再从当前时刻开启新片段，边界不重叠 |
| 应用退到后台 / 锁屏 / 灭屏 / 管控锁定 | **否** | `UsageEvents` 前后台事件序列 + 屏幕广播判定，立即暂停 |
| 重新进入目标应用 | 是 | 从暂停处继续：新片段累加到已有的 `perAppUsedMs`，不清零、不重复 |
| 前台无法确认 | — | 保持「最后已知应用」继续计时，避免静止看视频被误判为离开而丢时长 |

实现要点：`UsageAccess.isCountableForeground()` 统一排除桌面（动态 `CATEGORY_HOME` + 常见厂商桌面）、系统界面、权限弹窗、家长界面与未知前台；`GuardAccessibilityService` 在包名变化 / 回到桌面时调用 `UsageRepository.pause()` 并请求一次即时心跳，不再等待 1 秒轮询；`UsageAccess.recentForegroundState()` 同时处理 `MOVE_TO_FOREGROUND/ACTIVITY_RESUMED` 与 `MOVE_TO_BACKGROUND/ACTIVITY_PAUSED/ACTIVITY_STOPPED`，能明确区分「已离开」与「仍在应用内」；单次结算上限放宽到 5 分钟，避免后台服务被 ROM 冻结后丢时长（关机 / 熄屏仍由 `onScreenOff`、`onBoot` 截断并对账）。

- **计费单位**：「前台片段」。应用切换 / 窗口事件 / 灭屏 / 每 5 秒结算一次，写入 SharedPreferences；服务被杀或重启最多丢失 5 秒。
- **日期切换**：`DATE_CHANGED`、`TIME_SET`、`TIMEZONE_CHANGED` 广播 + 每次心跳双重检查；跨天清零每日总用量、各应用用量、连续用量与提醒标记，**保留配置**；未结束的强制休息继续保留，避免通过跨天绕过。
- **设备重启**：`BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` 拉起常驻服务；同一天的每日计数**不清零**，并用系统「使用情况访问」数据对账取较大值，防止重启刷时长；持续中的休息期继续生效。
- **应用切换**：关闭旧片段并把时长归属到旧应用，再开启新片段；单应用限额按包名独立累计。
- **锁定 / 休息 / 灭屏期间不计时**；熄屏超过 5 分钟视为新的连续使用段。
- **降级前台检测**：无障碍服务未开启时，用 `UsageEvents` 最近一次前台切换事件兜底识别当前应用。

### 时间重置（一键恢复到预设初始状态）

主界面「实时状态」下方有独立的 **「时间重置」** 卡片与「重置今日计时」按钮，需通过家长密码验证并二次确认，属于明确的、不可误触的重置入口。

| 环节 | 恢复到初始状态的内容 |
| --- | --- |
| 本地 `pg_usage` / `pg_usage_<对象id>` | 今日总用量、各应用累计、单次连续用量、强制休息截止、进行中 / 暂停的片段与包名、熄屏锚点、结算锚点、每日 / 单次预警标志、休息结束播报标志；日期回到当天 |
| 共享数据集 `SubjectTiming` | 当前监控对象在所有设备上的计时分量全部清空，并推进「重置纪元」 |
| 进程运行态 | 休息进度分母、锁定 / 拦截 / 提示去重键、通知去重缓存、全屏遮罩 |
| 展示 | 主界面两项剩余值、进度条、休息倒计时、状态文案与下拉通知栏立即重算 |

**覆盖的常见情况**：计时进行中（丢弃未结算片段，下一秒从重置时刻重新计时）、已暂停（停在桌面时不会开始计时，重新进入应用才计时）、强制休息中（倒计时与遮罩一起消失）、每日 / 单应用时长已用完（立即解除时间类锁定），以及日期异常、时间戳回拨、持久化数据损坏等异常状态。任何情况下结果都等于「新安装 / 跨天首次使用」的初始状态；重复点击重置结果完全一致，不会重复累计、不会回退。

**不修改**：管控规则与时长上限、启用全部管控规则总开关、应用白名单、单应用限额、家长密码、四项提示设置、监控对象列表与局域网连接设置。写入目标只有 `pg_usage` 与 `pg_share` 的计时部分，配置文本原封不动；重置只作用于**当前激活的监控对象**，其他对象的数据不变。

**异常与降级**：本地计时写入失败时整体返回失败并明确提示；共享层未初始化、服务未运行、无网络或同步失败时，本机重置依然成功，界面按降级路径读取已清零数据，后续 8 秒同步周期会自动补齐。每一步独立捕获异常，不会因共享层或通知刷新失败而回滚已完成的重置。

**跨设备一致性**：重置会推进 `SubjectTiming.epoch`（`固定 20 位毫秒时间戳|设备ID`，字典序即新旧顺序）并立即发起一次同步。`DeviceClock.absorb()` 与 `SubjectTiming.absorb()` 只合并同一纪元的分量：旧纪元数据一律丢弃，因此其他设备即使回放重置前的旧分量也不会把时长拉回；各设备收到新纪元后本地分量从零重建，随后按原有 G-Counter 规则继续正常累计。共享页更新记录会新增一条「[时间重置] 重置当前监控对象的全部计时」。

## 四、局域网本地共享（完全离线，无云服务器）

### 4.1 能力概览

| 能力 | 实现 |
| --- | --- |
| 本机建服务器 | 应用内 `java.net.ServerSocket` 手写极简 HTTP/1.1，默认端口 `8765`（可改 1024~65535） |
| 自动发现 | UDP `8766` 广播 `PG_DISCOVER_V1`，服务器回 `PG_SERVER_V1` + 端口 + 设备 ID + 服务器名称（设备型号）；也支持手动填 `http://IP:端口` |
| 服务器名称 | **固定使用设备型号**（`Build.MODEL`），无需手动填写；UDP 应答、ping、更新记录与共享页展示统一取同一值（详见 4.8 节） |
| 持久化 | `SharedPreferences(pg_share)` 保存全量数据集、连接设置、设备 ID；进程被杀 / 设备重启后由 `init()` 完整恢复并按保存的地址自动重连 |
| 多设备一致 | 8 秒自动同步，配置变更 / 对象操作立即触发；服务端合并结果是权威数据集，客户端整体替换，最终收敛到同一份 |
| 同步范围 | 「启用全部管控规则」「应用白名单」仅本机生效，不进入共享数据集；其余规则、计时、对象与记录同步（详见 4.7 节） |
| 多监控对象 | 创建 / 切换 / 重命名 / 删除；默认对象沿用旧 `pg_config` / `pg_usage`，其他对象使用 `pg_config_<id>` / `pg_usage_<id>` 独立分区 |
| 更新记录 | 每个对象最多 50 条，记录时间、设备、动作、详情、数据版本；界面列出最近 12 条 |

> 数据只在本机与同一 Wi-Fi 内的设备之间传输，工程中不含任何云端地址、账号或上传逻辑；HTTP 明文仅在局域网内使用（Manifest 开启 `usesCleartextTraffic`）。每台设备首次启动会生成稳定的 UUID 作为写入者标识。「启用全部管控规则」与「应用白名单」属于仅本机字段，不参与此处的数据传输。

### 4.2 内置接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/ping` | 连通性探测，返回设备 ID / 服务器名称（设备型号） / 当前版本 / 端口 |
| GET | `/api/state` | 读取全量共享数据集 |
| POST | `/api/sync` | 提交本地数据集与 `baseRevision`，服务端串行合并后返回权威全量数据集与冲突明细 |
| PUT | `/api/subjects/{id}` | 提交单个监控对象（服务端按同一规则合并） |
| DELETE | `/api/subjects/{id}` | 删除监控对象（写 tombstone） |

请求体上限 512 KB；JSON 非法 / 字段越界返回 400 并给出明确原因，服务端内部异常返回 500；所有写操作都在 `ShareStore` 的同一把锁内串行完成，多个设备的并发 HTTP 请求不会交叉写。

### 4.3 并发访问与同步冲突

| 数据类型 | 冲突裁决规则 | 效果 |
| --- | --- | --- |
| 对象名称 / 元数据 | `(updatedAtMs, writerId)` 字典序较大者胜 | 多设备同时改名结果确定，与同步先后顺序无关 |
| 规则配置（共享字段） | `(configUpdatedAtMs, configWriterId)` 较大者胜 | 后改的配置覆盖先改的，不会互相回退；「启用全部管控规则 / 应用白名单」不参与裁决，始终取本机值 |
| 计时数据 | 按设备的 G-Counter 分量，同一设备逐字段取 `max` | **不重复**（同一段只算一次）、**不回退**（单调递增）、**不丢失**（各设备增量独立保留） |
| 全局总时长 | 各设备分量求和 | 多设备使用时长正确叠加 |
| 单应用全局时长 | 同一应用跨设备分量求和 | 单应用限额跨设备生效 |
| 连续使用时长 | 取各设备最大值，**不跨设备相加** | 连续使用是单设备概念，避免虚增触发休息 |
| 更新记录 | 按「时间 + 设备 + 动作 + 详情」去重后合并 | 多设备记录都保留，按时间倒序 |
| 删除 | tombstone，任一侧标记删除即保持删除 | 旧设备回放不会把已删对象复活 |
| 跨天 | 按日期隔离，旧日分量整体清零 | 昨天的时长不会串进今天 |

客户端提交时携带 `baseRevision`，若落后于服务端当前版本则记录「并发写入」并以服务端合并结果为准；冲突**不拒绝写入**，界面用橙色提示「检测到并发修改，已自动合并」并列出明细。`UsageRepository.snapshot()` 取「本设备本地数据」与「全局汇总数据」的逐字段较大值交给规则引擎：远端累计不会覆盖本地，本地也不会把远端增量重复记进自己的分量，因此不会出现 A 累加 B、B 再累加 A 的循环放大。计时上报用的是不含远端叠加的 `localSnapshot()`。

### 4.4 状态提示（原因可区分）

| 状态 | 界面文案 | 常见原因 |
| --- | --- | --- |
| `IDLE` | 未启用局域网共享 / 已断开共享连接 | 尚未开启服务器，或主动断开 |
| `SERVER_RUNNING` | 本机服务器运行中（等待其他设备连接） | 本机已监听端口，界面同时显示可分享的本机地址 |
| `CONNECTED` | 同步成功 / 已连接局域网服务器 | 正常，绿色 |
| `CONFLICT_MERGED` | 检测到并发修改，已自动合并 | 多设备同时修改，橙色并列出冲突明细 |
| `SERVER_NOT_STARTED` | 本地服务器未启动 | 目标地址指向本机，但本机服务器未开启 |
| `UNREACHABLE` | 服务器地址不可达 / 地址无法解析 / 连接超时 | IP 或端口错误、对方未启动服务器、不在同一 Wi-Fi |
| `DISCONNECTED` | 与服务器的连接已中断 / 连接超时，可能已离开该局域网 | 曾经连上过、之后断开（与首次就不可达明确区分） |
| `SYNC_FAILED` | 同步失败 / 服务器返回错误 | HTTP 非 2xx、JSON 校验失败、数据集异常 |

连接超时 4 秒、读取超时 6 秒；断开期间本机仍按已保存数据继续计时与执行全部规则，恢复连接后自动补同步。状态区还显示「最近同步」时间与本机地址。

### 4.5 使用步骤

1. 在**一台**设备（例如家长的手机）打开主界面 →「局域网共享与监控对象」→ 打开「本机服务器」开关，记下界面显示的 `http://本机IP:8765`。
2. 其他设备在同一 Wi-Fi 下打开同一页面 → 点「自动发现」选择该服务器，或手动填入上面的地址 → 点「连接」；状态变绿即已接入。可用「测试连通性」单独排查网络。
3. 在「监控对象」区域新建 / 切换 / 重命名 / 删除对象；每个对象卡片显示累计时长、最近更新时间、记录数、是否正在计时，页面底部列出当前对象最近 12 条更新记录。
4. 任一设备修改配置、切换对象或产生计时都会写入共享数据集并同步；「立即同步」可手动触发。
5. 「断开」只停止同步，本机数据保留；重新「连接」即从已保存状态继续，不需要重新配置。

### 4.6 数据校验、异常隔离与持久化恢复

- 对象 ID / 名称 / 端口 / 时长均做范围校验：对象数 ≤ 100、名称 ≤ 64 字符、端口 1024~65535、单个时长字段 ≤ 30 天；`schema` 版本不匹配、JSON 非法、字段越界一律拒绝写入或回落安全默认值。
- 网络操作全部在后台线程；服务端单请求异常返回 500 且不影响 accept 线程；客户端按异常类型（`ConnectException` / `SocketTimeoutException` / `UnknownHostException` / 其他）映射上表不同状态。
- 共享层任何异常都被捕获并降级：不会阻断本地配置保存、计时、规则判定与界面。`UsageRepository.snapshot()` 先取本地快照并释放锁、再访问共享层，避免锁顺序倒置造成死锁。
- 计时更新记录最多 30 秒一条，避免 1Hz 心跳刷满记录；界面每秒刷新，对象列表按内容指纹做 3 秒节流。
- 进程重启恢复路径：`ShareStore.init()` 读回数据集与设置 → 按持久化开关重启本机服务器 → `ShareSync.init()` 注册全局计时提供者、启动 8 秒同步循环并立即重连一次 → 请求一次即时心跳刷新规则判定。

### 4.7 同步范围：总开关与三类名单仅本机生效

「**启用全部管控规则**」与「**三类应用名单**（可玩 / 休息放行 / 免计时）」被设为**仅本机字段**：每台设备各自独立保存，不写入共享数据集。各设备安装的应用不同，名单本身也不具备跨设备意义。典型场景是家长手机临时关闭总开关做配置、孩子的设备仍继续受管控；或每台孩子的设备允许不同的应用，彼此不覆盖。

| 配置项 | 是否同步 | 存储位置 |
| --- | --- | --- |
| 启用全部管控规则 `masterEnabled` | **不同步** | 本机 `pg_config` / `pg_config_<对象id>` |
| 可玩白名单 `whitelist.enabled` + `whitelist.packages` | **不同步** | 同上 |
| 休息放行 `restWhitelist.packages` | **不同步** | 同上 |
| 免计时 `noCountWhitelist.packages` | **不同步** | 同上 |
| 每日设备总时长、单次连续 + 休息时长、单应用每日限额 | 同步 | 共享数据集 `configJson` |
| 有声 / 人声 / 拦截出声 / 图形提示开关、家长密码 | 同步 | 共享数据集 `configJson` |
| 计时数据、监控对象、更新记录 | 同步 | 共享数据集 |

实现分三步，任一环节都保证这两项不会跨设备流动：

1. **上行剔除**：`RulesConfig.toShareJson()` 在完整配置 JSON 上移除 `masterEnabled`、`whitelist`、`restWhitelist`、`noCountWhitelist`，并写入 `localFieldsOmitted` 标记。共享数据集的 `configJson`、HTTP 报文与更新记录里都不含这两项。
2. **下行保留**：`ConfigRepository.applyShareJson()` 把服务器裁决的共享字段覆盖本机，再用本机当前值深拷贝回填这四类字段。即使收到旧版本（仍带这两字段）的数据集也不会被覆盖；内容未变化时跳过写盘与界面刷新。
3. **无谓变更抑制**：`ShareStore.recordConfigChange()` 先把新共享快照与现有 `configJson` 做文本比对，内容相同直接跳过。因此只改本机总开关 / 三类名单**不会**提升数据版本、不会刷新 `configUpdatedAtMs`、不会写更新记录、不会发起同步，也不会用较新的时间戳压过其他设备真正的配置修改。

配套行为：

- **切换 / 新建监控对象**：`ConfigRepository.switchScope()` 从共享配置初始化新分区时沿用本机当前的四类设置，不会把三类名单清空或把总开关重置；每个对象仍各自独立。
- **全链路净化**：`ShareStore` 在启动恢复、服务端合并（`mergeRemote`）与客户端应用（`replaceWith`）三个入口统一调用 `RulesConfig.normalizeShareJson()` 剥离历史残留字段，保证持久化数据与 HTTP 报文都不含这两项；归一化幂等，损坏数据回落空串。
- **界面标注**：主界面总开关卡片、应用名单规则卡片（标题带「· 仅本机」）、名单管理页与共享设置页均明确提示「仅本机生效，不同步到局域网其他设备」，其他控件与交互不变。

> 其余规则、计时数据、监控对象与更新记录仍按 4.3 节的冲突规则在设备间保持一致；本改动不影响规则判定、计时累计、强制休息、白名单拦截与秒级展示。

### 4.8 服务器名称使用设备型号

服务器名称**固定取本机设备型号**（`android.os.Build.MODEL`），不需要也不能自定义：

| 使用位置 | 取值 |
| --- | --- |
| UDP 自动发现应答 `PG_SERVER_V1` 第 3 段 | `ShareStore.deviceName()` |
| `GET /api/ping` 的 `deviceName` 字段 | 同上 |
| 共享页「服务器名称」展示、更新记录里的设备列 | 同上 |
| 首次创建的默认监控对象名称 | 同上；旧版本已保存的「默认设备」在启动时一次性迁移为设备型号 |

名称会剔除会破坏 UDP 报文分隔的 `|` 与换行、截断到 64 字符，型号不可读时兜底为「Android 设备」。启动时忽略持久化里的历史自定义名称并强制写回型号，因此同一台设备在不同入口显示的名称始终一致；其他设备「自动发现」列表与「测试连通性」看到的就是对方的设备型号，便于在多台设备里分辨要连接哪一台。

## 五、界面与提示（儿童不识字也能理解）

**主界面已分页**，顶部标签栏固定，下方只切换内容，不再是一条长滚动列表：

| 页面 | 内容 |
| --- | --- |
| 概览 | 总开关与服务状态、实时状态（可用时长 / 连续时长 / 休息倒计时 / 前台应用 / 单应用剩余）、时间重置 |
| 规则 | 四张规则卡片：每日总时长、连续使用与强制休息、应用名单（可玩 / 休息放行 / 免计时）、单应用每日时长 |
| 提示 | 儿童提示方式四个开关、试听与媒体音量、家长密码、局域网共享入口、使用说明 |
| 设置 | 运行所需权限逐项检测、版本与更新 |

分页只切换可见性，各页滚动位置与 1 秒刷新保持不变；家长停留的页面会记住，下次打开直接回到该页（首次进入固定落在「概览」）。

- 概览页每秒刷新：状态（可用 / 已锁定）、**全部锁定原因**、今日剩余时长与进度条、本次连续剩余时长与进度条、**强制休息倒计时**、当前前台应用、各单应用今日剩余时长。
- **全屏限制遮罩（每日总量 / 强制休息）**：112dp 大图标（蓝色月亮 / 紫色时钟）、34sp 儿童短句（「该休息啦」「今天用完啦」）、46sp 超大倒计时与进度条。规则标题、全部命中原因、今日已用时长等文字缩小为家长辅助说明。白名单 / 单应用超额这类「仅当前应用」限制不弹全屏遮罩，只用短时图形卡片，避免盖住桌面。
- **拦截图形卡片**：打开白名单外 / 超额应用时先返回桌面，再弹出约 2.4 秒的鲜艳色卡片（大图标 + 34sp 短句，如「不能玩哦」「今天玩够啦」）。窗口不可触摸、不抢焦点，不阻挡孩子操作桌面。
- **内置中文语音播报**：8 条真人中文短句 mp3 随 APK 打包在 `res/raw`，由 `MediaPlayer` 直接播放，例如「这个应用不能玩哦，已经帮你回到桌面啦」「该休息啦，让眼睛歇一歇，休息好了再玩」「休息好啦，可以再玩一会儿」。**不依赖系统 TextToSpeech 引擎、不依赖中文语音包、不联网、不需要额外权限**，装好即可朗读；2.5 秒去重避免重复播报，媒体音量低于 60% 时临时调高、播完自动还原。
- 常驻通知：显示剩余时长 / 休息倒计时 / 锁定原因，点击回到主界面（家长向，保留文字）。
- **声音提醒**：到点前 1 分钟预警、进入锁定、进入休息、休息结束、拦截应用时振动；人声语音开启时播报内置语音，关闭时改播系统通知音，两者不叠加。
- **家长密码**：默认 `1234`，可在「修改家长密码」中改为 4~8 位数字或留空关闭；冷启动及从锁定遮罩进入家长设置时均需验证。

- **「提示」页的「局域网共享与监控对象」按钮**：一键进入共享设置页，可开启本机服务器、连接其他设备、管理多个监控对象（详见第四节）。
- **概览页「时间重置」卡片**：位于「实时状态」下方，提供「重置今日计时」按钮 + 二次确认；重置后主界面、通知栏、遮罩与运行状态立即同步刷新（详见第三节）。

### 计时信息：精确到秒 + 通知栏下拉即看

主界面「实时状态」卡片把两项数值拆开独立显示，标签与数值一一对应，统一为 `00 时 00 分 00 秒` 格式（时、分、秒三段始终保留，不省略小时），每秒刷新：

| 项目 | 主界面标签 | 同卡片辅助信息 |
| --- | --- | --- |
| 剩余可用时长 | 可用时长（时 / 分 / 秒） | 今日已用 `00 时 00 分 00 秒` |
| 单次使用连续剩余时间 | 单次使用连续剩余时间（时 / 分 / 秒） | 本次已连续 `00 时 00 分 00 秒` |

**工具栏下拉即可查看，无需跳转页面**：常驻通知折叠状态两行分别显示「可用时长 …」「单次连续剩余 …」；继续下拉展开后，用系统大文本样式同时列出这两项数值、今日已用、本次已连续、运行状态、限制原因、休息倒计时与当前应用。通知每秒刷新，采用低重要性渠道 + `setOnlyAlertOnce(true)`，刷新不会产生提示音、振动或横幅；点击通知仍回到主界面，其余交互完全不变。

数据来源与刷新：`UsageRepository.localSnapshot()` 把当前前台片段的未结算增量按当前时间实时计入，因此两项剩余值每秒递减 1 秒；退出到桌面、切到后台、锁屏灭屏时计时暂停，数值保持不变（这是预期行为，不是刷新停滞）。若服务被系统短暂冻结，主界面会自动回退到直接读取本地快照，仍按秒继续显示。规则判定、计时累计、强制休息、白名单拦截与局域网共享同步逻辑均未改动。

## 六、权限（首次使用必须全部开启）

「设置」页的「运行所需权限」区域会实时显示每项状态并提供跳转按钮：

| 权限 | 用途 | 授予路径 |
| --- | --- | --- |
| 使用情况访问 | 统计前台时长、重启对账 | 设置 → 应用 → 特殊权限 → 使用情况访问 |

| 通知（Android 13+） | 常驻服务通知；下拉通知栏可直接查看两项秒级时长 | 运行时弹窗授权 |
| 忽略电池优化 | 避免后台服务被系统冻结 | 设置 → 电池 → 电池优化 |
| 互联网 / 网络状态 / Wi-Fi 状态 | **仅**用于局域网内 HTTP 通信、UDP 自动发现与读取本机 IP | 普通权限，安装即授予，无运行时弹窗；不访问任何云端服务 |

缺少悬浮窗权限时，图形卡片降级为系统 Toast（文字），语音播报仍可用；服务仍会周期性把设备送回桌面兜底执行限制，但无法展示遮罩，请务必开启。

**中文语音不需要任何权限或系统组件**：语音是打包在 APK 内的 mp3，不是设备文字转语音（TTS）引擎，因此设备没有 TTS 引擎、没有中文语音包、处于离线状态都不影响朗读。仅受系统媒体音量 / 勿扰模式影响，界面会显示当前媒体音量便于排查。

## 七、构建与安装

### 方式 A：Android Studio（推荐）
1. 使用 Android Studio（Giraffe 及以上）打开 `ParentalGuard` 目录；
2. 确保已安装 SDK Platform 34 与 Build-Tools 34.0.0，JDK 17；

```bash
# 需要 JDK 17、Android SDK（platforms;android-34、build-tools;34.0.0）
export JAVA_HOME=/path/to/jdk-17

./gradlew assembleDebug        # 调试版
```

### 计时与共享算法自检（可选）

```bash
python tools/verify_timing.py
# 输出：ALL CHECKS PASSED
```

## 九、版本更新检查与发布

「设置」页新增「版本与更新」卡片，读取本机 `versionName` 与 GitHub Releases 的最新 tag 比较：

| 情况 | 判定 | 界面表现 |
| --- | --- | --- |
| 远端版本更高 | 有更新 | 弹窗列出当前 / 最新版本、发布时间与发布说明，提供「下载安装包」与「发布页」两个入口 |
| 远端版本相等或更低 | 已是最新 | 绿色状态行；手动检查时追加 Toast |
| API 返回 404 | 仓库尚无正式发布 | 黄色提示，不按失败处理 |
| 超时 / 无网络 / 非 2xx | 网络失败 | 红色显示具体原因；启动时的自动检查失败不弹窗打扰 |
| tag 或本机版本号无法解析 | 格式异常 | 黄色提示指明是哪个版本号不合法，不做错误比较 |

- 触发方式：**启动时自动检查**（受 12 小时间隔限制，`UpdatePrefs` 记录上次时间）+ 卡片上的**「检查更新」按钮**（需先通过家长密码）。
- 只访问 `api.github.com` 读取版本号与发布说明，**不上传任何本机数据**；版本比较只取数字段，`v` 前缀与 `-beta` 之类后缀会被忽略。
- 下载走系统浏览器 / 下载器打开 Release 附件地址，覆盖安装不会影响本机已有的规则与计时配置。
- 版本比较逻辑有单元测试覆盖（`app/src/test/java/.../VersionCompareTest.kt`，含缺段、前缀、预发布后缀与格式异常）。

**发布流程**（详见 `docs/RELEASE.md`）：

```bash
./tools/release.sh 1.0.1                 # 本机构建 + 验签 + 核对包内版本号，产物落在 Release/ 目录
./tools/release.sh 1.0.1 --push           # 提交安装包与版本号、打 tag 并推送，由 CI 发布 Release
./tools/release.sh 1.0.1 --upload         # 或用本地产物直接创建 / 覆盖 Release（需 gh 已登录）
```

`v*` tag 推送后，`.github/workflows/release.yml` 只做「校验产物 → 生成发布说明 → 创建 Release」：
核对 APK 是否存在、`sha256` 是否一致、`aapt2` 读出的包内 `versionName` 是否等于 tag，任一不符直接失败。
附件为 `ParentalGuard-v<版本>.apk` 与其 `.sha256`。

**签名只在本机完成，CI 不需要任何 Secret**：私钥既不在仓库里，也不进 Actions，CI 仅用自带的
`GITHUB_TOKEN` 创建 Release。代价是发布包需本地构建后提交（与仓库保留历史 APK 的做法一致）。

## 十、已知限制

- 本应用使用「无障碍服务 + 悬浮窗 + 使用情况访问」实现**普通应用级**管控，未使用 Device Owner / Device Policy Manager（后者需要设备管理器 provisioning，普通安装无法获得）。因此：手势导航的系统级操作、通知栏快捷设置、部分厂商分屏/小窗无法 100% 拦截；儿童仍可能通过系统设置强行关闭无障碍服务，建议配合系统「屏幕固定」或设备自带家长控制使用。
- 部分国产 ROM 会主动冻结后台服务，需加入电池优化白名单 / 自启动白名单 / 后台锁定。
- 内置语音走媒体音量 `STREAM_MUSIC`：媒体音量过低、静音或勿扰模式下可能听不见。应用会在播报时临时把媒体音量提到 60%、播完还原；若设备禁止应用调整音量，请家长点「媒体音量设置」手动调高。图形卡片、振动与限制执行在任何情况下都有效。
- 内置语音是固定 8 条短句（真人录音式合成音频），不能朗读任意自定义文本；新增提示场景需同步修改 `KidPrompt.cueOf()` 与 `tools/generate_voice.py` 并重编 APK。
- 图形卡片与锁定遮罩依赖悬浮窗权限；未授权时降级为系统 Toast + 语音播报 + 周期性返回桌面。
- `QUERY_ALL_PACKAGES` 用于列举应用，上架 Google Play 需提交权限声明；侧载与国内应用商店不受影响。
- targetSdk 固定为 33，以规避 Android 14 对前台服务 `specialUse` 类型的审核要求；在 Android 14+ 设备上仍可正常安装运行。
- 关闭人声语音后的提示音使用系统默认通知音，静音 / 勿扰模式下可能被系统抑制。
- **局域网共享仅适用于可信 Wi-Fi**：为保持零依赖、零账号，HTTP 接口未做身份认证与加密，任何能访问该 IP 与端口的设备都能读写共享数据集。请勿在公共 Wi-Fi 使用；同一时间建议只由一台设备开启服务器，其他设备连接它。
- UDP 自动发现依赖路由器允许广播；开启「AP 隔离 / 访客网络 / 客户端隔离」的路由器会丢弃广播，此时请用界面显示的 IP 手动连接。
- 服务器设备关机或应用进程被杀后，其他设备会显示「连接中断」，并继续使用本机已保存数据；服务器恢复后自动补同步，按设备分量合并不会重复累计。
- 冲突裁决使用各设备的本地时钟：若设备间时间偏差很大，「后改者胜」可能偏向时间较新的设备；建议同一局域网内设备都开启自动对时。跨天判定同样以各设备本地日期为准。
- 共享数据保存在本机 `pg_share` 中，卸载应用或清除应用数据会清掉本机副本；重新连接服务器可从服务器数据集恢复。
- 「启用全部管控规则」与「应用白名单」仅保存在本机：更换设备、恢复出厂设置或清除应用数据后需重新设置；服务器上的共享数据集不含这两项，无法替其他设备恢复。
- 新旧版本混用时，旧版客户端仍可能把这两项写入共享数据集（新版设备下行时会忽略，功能不受影响），但旧版设备读到新版发出的共享快照会把这两项回落为自身默认值。**建议同一局域网内的设备升级到同一版本**；新版应用启动时会归一化本机已有的历史数据集。
- 时间重置依赖共享数据集里的 `epoch` 重置纪元字段：旧版本客户端的数据集不含该字段，与新版混用时其上报的旧数据会被当作初始纪元，无法保证「重置后旧值不复活」。**执行时间重置前请让局域网内所有设备升级到本次版本**；本机未启用共享时不受此限制。
- 部分厂商会把前台服务的常驻通知归入「静默通知」分组或默认折叠，需在该通知上再下拉一次（或在系统通知设置里把「管控状态」渠道设为默认 / 提示）。折叠状态本身已同时显示两项秒级数值，主界面始终不受影响。
- Android 与部分 ROM 可能对高频通知刷新做合并限流，通知上的秒数偶尔会一次跳 2 秒；主界面的秒级显示与计时判定始终按 1Hz 精确执行，不受影响。
- 更新检查依赖 `api.github.com` 可达：网络受限时会显示「检查失败：连接 GitHub 超时」，不影响管控功能；Release 附件直链下载同样需要能访问 GitHub，受限环境请手动拷贝 APK 安装。未登录的匿名调用受 GitHub 每小时 60 次限流，本应用有 12 小时间隔限制，正常使用不会触发。
- 更新检查不校验安装包签名，只做版本号比较；请只安装本仓库 Releases 中的附件（可用附带的 `.sha256` 自行校验）。
